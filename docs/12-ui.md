# UI: button, slider/sliderv, timeout

## `button` — `src/js/classes/button.ts`

`button extends entity` — a clickable button with text. Adds a hitbox (inherited),
a `ButtonText` config and a debounce `timeout`.

```ts
new button(
    texture: TextureArg,
    [x, y]: Vec2,
    [width, height]: Vec2,
    [text, color, size, fontFamily]: [string, string, number, string],
    timeVal = 500,
)
```

- Registers itself in `engineState.buttons` (_and_ `objects`, via the entity
  superclass constructor).
- `ButtonText` (`src/js/classes/button.ts:8-19`) also carries `align`
  (`CanvasTextAlign`, default `"center"`), `baseline` (default `"middle"`) and
  cached `pos` (the resolved anchor the text is drawn at).

**Interactivity behavior** — `button.update()` (`src/js/classes/button.ts:53-71`):

1. If `disabled`, `hovered = false` and `clicked = false` immediately — a disabled
   button reports no interaction at all.
2. Otherwise `hovered = isHovering(hitboxes[0])`.
3. `clicked` is edge-triggered and latched by the `timeout`:
    - `isClicking(hitboxes[0]) && !timeout.active` → `clicked = true` and
      `timeout.start()`.
    - else if the timeout is inactive → `clicked = false`.
    - So `clicked` stays `true` for `timeVal` ms after a press (default 500), then
      clears — acting as a press latch that also smooths out multi-frame holds.
      While the timeout is active no second click registers.
4. Calls `super.update()` to refresh geometry.

Like all UI widgets, you must call `update()` every frame for it to track state;
`draw()` is separate. In the demo the `BOOM` button launches the player at max
speed on click, swaps its label to `"KABOOM!"` / `"recharging..."` and holds a
`timeout` cooldown.

**Drawing** — `button.draw()` (`src/js/classes/button.ts:73-114`) draws the entity
(super.draw) then the text at a resolved position:

- `align left` → `x`; `right` → `x + width`; `center`/default → `x + halfwidth`.
- `baseline top` → `y`; `middle`/default → `y + halfheight`; `bottom` → `y + height`.
- Draws via `drawText(text, pos, size, fontFamily, baseline, align, this.angle, this.alpha)`
  — so the button's _rotation_ and _alpha_ propagate to the label.

`destroy()` is inherited from `entity` (sets `toDelete`) and the sweep removes it
from `objects`, `buttons` and `hitboxes`.

## `slider` / `sliderv` — `src/js/classes/slider.ts`

Both are thin wrappers over an internal `_slider` that takes the orientation
(`slider` = horizontal, `sliderv` = vertical).

```ts
new slider(bgTexture, thumbTexture, fillTexture, [x, y], [width, height],
           thumbSize, [min, max], currentValue, step?)
new sliderv(... same, thumbSize = thumbHeight ...)
```

- Pushes itself into `engineState.sliders`.
- Clamps `currentValue` into `[min, max]` and stores it as the **`percentage`**.
  `min`/`max` here are _value_ bounds, not percentages — the slider maps `[min, max]`
  linearly onto the track, and `percentage` reports the current value.
- `step` (optional, last arg) snaps `percentage` to multiples of `step` based at
  `min` — so `[0, 24]` with `step: 4` gives `0, 4, 8, ... 24`. Omit it (or pass
  `0`/`undefined`) for continuous values. The initial `currentValue` is snapped too.
- Builds three texture **parts**:
    - `background` — a `SliderPart` (`usingColor`, `color`, `texture`).
    - `thumb` — a `SliderThumb` (adds `x/y/width/height`, `blocked`, `borderRadius`).
    - `fill` — a `SliderPart & { inverted }`.
- Sizes the thumb (`thumbSize` along the drag axis; if `thumbSize > half the
track`, the thumb is shrunk to a square of the _cross_ dimension, so an oversized
  thumb clamps sensibly), positions it from the initial percentage.
- Creates two hitboxes: `hitboxes[0]` = track (attached to the slider), `hitboxes[1]`
  = thumb (attached to `this.thumb`, a plain object) — plus the `draw()` composite
  helper.

### Drag behavior (the interesting part) — `update()` (`src/js/classes/slider.ts:182-254`)

Each frame:

1. **Hover/click state:** `hover = isHovering(track) && !thumb.blocked`;
   `click = isClicking(thumbHitbox, /* don't consume */ true)` when hovering.
2. **Grab:** when no drag is active, if a pointer is over the thumb hitbox and is
   `down` and unattached (`attached === undefined`), the slider claims it:
    - `pointer.attached = this`, `drag.pointer = pointer`,
    - `drag.offset` = pointer position minus thumb position, so the thumb doesn't
      jump to the cursor.
3. **Drag:** while `drag.pointer` exists and remains `down`, the thumb follows the
   pointer along its axis, clamped to the track; `percentage` is recomputed from
   the thumb's position:
    - horizontal: `maxX = x + width - thumb.width`, thumb in `[x, maxX]`;
      `percentage = ((thumb.x - x) / (width - thumb.width)) * (max - min) + min`.
    - vertical mirrors this with `height`/`thumb.height`.
4. **Release:** when the pointer is no longer `down` (or disappeared), the pointer's
   `attached` is cleared and the drag state resets.
5. **Refine+sync (always):** `percentage` is clamped to `[min, max]`, **snapped to
   the `step` grid** (if one was given) and **rounded to 2 decimals**
   (`Math.round(p * 100) / 100`), then the thumb is repositioned from the ratio so
   programmatic `percentage` writes are honored. A stepped slider's thumb therefore
   jumps between grid positions as you drag.
6. Recomputes `halfwidth`/`halfheight`/`anchor`.

`blocked` freezes the whole thing: `hover`/`click` are suppressed and grabbing is
skipped; the thumb keeps its last position, so you can use `blocked` to "disable"
a slider without destroying it.

### Fill

`fill.inverted` flips the fill so it grows **from the opposite end** (right/up
instead of left/down) — the fill rect is mirrored across the track
(`src/js/classes/slider.ts:304-320`). Non-inverted fill grows from the start
toward the current percentage (plus half a thumb stop).

### `draw()`

Saves, translates to the anchor, rotates (entity-style), sets alpha, clips to the
rounded rect, then stamps, in order: **background**, **fill** (sized to the
percentage), **thumb** (its own rounded clip). `drawPart` handles both solid-color
and image parts (`src/js/classes/slider.ts:36-51`). Particles/text on top are
user-drawn.

### `setTexture(bg, thumb, fill)` / `destroy()`

- `setTexture` re-applies the three parts.
- `destroy()` sets `toDelete` **and** splices both hitboxes out of
  `engineState.hitboxes` immediately (the thumb's hitbox isn't owned by the slider,
  so the per-frame sweep would miss it) — see
  [boot-and-lifecycle](03-boot-and-lifecycle.md#special-case-sliders).

### Public fields you interact with

`hover`, `click`, `percentage` (the value), `step` (optional snapping grid — set
any time), `blocked`, `fill.inverted`, `thumb` (`x/y/width/height`,
`borderRadius`, part textures), `orientation`, `angle`, `alpha`, `borderRadius`.

## `timeout` — `src/js/classes/timeout.ts`

A timed self-resetting boolean:

```ts
const t = new timeout(500)
t.start() // active → true
t.active // true for 500ms, then false
```

- `start()`: no-op while already active; sets `active = true`, stamps
  `currentTime`, schedules a `setTimeout` that resets `active`/counters after
  `this.time` ms.
- While active, a self-repeating poll (`updateTime` = 75ms) refreshes
  `timeElapsed` (= since `start`) and `timeLeft` (= `max(0, time - elapsed)`).
- Fields: `time` (duration), `active`, `currentTime`, `timeElapsed`, `timeLeft`,
  `updateTime`.
- Used by `button` to latch the clicked state: the click stays `true` until the
  timeout clears, and presses during it are ignored.

## Behavior notes

- **All three widgets must be `update()`d + `draw()`n in your loop** — the engine
  tracks state but does not auto-run UI.
- Buttons/sliders register globally (`buttons`/`sliders`/`objects`/`hitboxes`), so
  the GUI and the disposal system see them without extra wiring.
- `isClicking` on the button _consumes_ the click (default), so two overlapping
  buttons won't both trigger from one press; the slider uses the non-consuming
  variant because it manages `pointer.attached` itself.
